# brief：一个形状的 12 种界面（方案 A · 原版复刻）

参考：@twoclipping「纯代码 UI 动效」（X 收藏 20,060），提示词原文见 `.claude/skills/xilo-opus-video/references/viral-prompts.md` 的 A。只学结构和手法。

```text
<role>
你是一位动态设计师，也是一位创意程序员，擅长用代码做出有设计感的视频。
</role>

<inputs>
主题：一个形状不切镜头，连续变形成 12 种界面组件，展示 Dribbble 级 UI 动效。
想让观众记住的一句话：一个元素，十二种状态，每一拍都有动作。
原材料：无（纯代码，不用外部图片和素材）。
规格：14 秒（7 小节），1920×1080（16:9，用户指定），60fps，4 子帧运动模糊。
品牌：暖灰画布 #ECEAE6，组件黑 #0A0A0A / 白 #FFFFFF，关闭态灰 #C9C6C0，次要文字 #8A8A8A；字体 Geist（项目内 fonts/ 本地加载）。
声音：代码合成配乐 120 BPM（底鼓、拍手、闭镲、贝斯、和弦铺底），界面音效（点击、变形、拨动、打字、成功提示）落在动作帧；不配音。
</inputs>

<direction>
风格：Dribbble 级界面动效。全片只有一个形状，从不切镜头：每个状态都是同一个元素改变宽、高、圆角和颜色，内容用短暂的模糊切换。光标驱动每一次变化，真实的点击和拖拽。
整片只用一套风格、一套配色，同一个元素在每个镜头里的样子都一致。
画面上的字少而大；动画全部用闭式弹簧，最多一点点回弹。
镜头：随状态推拉，让每个状态占满画面（宽约 50%，高约 45%）；镜头用沉稳的弹簧（w 9，ζ 0.95）。
循环：最后一帧和第一帧完全一样，包括光标位置和静止速度。
禁止：弹跳缓动、粒子爆炸、发光、界面上的渐变、图标描边粗细不一、空拍、模板感、深色背景居中大字、所有元素同时淡入。
</direction>

<structure>
节拍网格：120 BPM，每拍 0.5s，7 小节 = 28 拍；每拍都有事件，重拍（每小节第 1 拍：0/2/4/6/8/10/12s）放最大的变化。
小节 1｜0.0–2.0s　光标停在「Get started」按钮上 → 0.5s 点击（按下缩放）→ 1.0s 收成加载圈，加载弧旋转。
小节 2｜2.0–4.0s　2.0s 变对勾（描线）→ 3.0s 拉宽成灵动岛（Now playing + 跳动的声波条）→ 3.5s 光标移向灵动岛。
小节 3｜4.0–6.0s　4.0s 点击，展开成音乐播放器（封面、歌名、播放键、进度条）→ 4.5s 点击播放，三角形变暂停 → 5.0–5.9s 抓住进度条圆钮拖动，进度直接由光标位置算。
小节 4｜6.0–8.0s　6.0s 播放器收成音量条 → 6.5–7.4s 往右拖到底再拖过头，条被拉长（橡皮筋）→ 7.5s 松手，从当时位置弹回。
小节 5｜8.0–10.0s　8.0s 音量条缩成开关（关闭态灰）→ 8.5s 点击，开关在拍点上翻转（圆钮两条边走不同弹簧，前沿先到）→ 9.0s 圆钮流动成标签指示条（Day / Week / Month）→ 9.5s 点 Week，指示条前沿拉伸。
小节 6｜10.0–12.0s　10.0s 标签展开成折线图，线自己画出来 → 10.5s 光标悬停，提示框弹出 → 11.0s 收成 ⌘K 命令面板（白底）→ 11.25–11.6s 打字「exp」→ 11.6s 筛出「Export chart」一行。
小节 7｜12.0–14.0s　12.0s 回车 → 变成黑色提示「Chart exported」→ 13.0s 提示变回「Get started」按钮，光标回到起始位置 → 14.0s 与首帧完全一致。
</structure>

<build>
1. 画面：单个 HTML 文件（index.html），HTML/CSS/SVG，Geist 本地字体，不用外部图片和素材。
2. 页面暴露 window.render(t)，画出第 t 秒；所有样式在 render(t) 里由 t 算出来：不用 CSS transition、计时器，帧和帧之间不保存状态。
3. 弹簧是闭式阶跃响应；一个值多次改变目标时，是每次改变各自一个弹簧的叠加，仍是 t 的纯函数（lib.js 的 track）。
4. 指示条和开关圆钮的两条边各走不同弹簧，前沿拉伸领先后沿。
5. 拖拽是直接操控：按住时数值由光标位置算出；松手后从当时的位置弹回。
6. 音效时间表从 index.html 的同一份事件表导出（window.EVENTS），配乐按同一节拍网格合成；混音后 -14 LUFS，峰值低于 -1 dBTP。
7. 渲染：Playwright 逐帧调用 render(t) 截图，每帧 4 子帧，ffmpeg tmix 混合成 60fps 运动模糊。
8. 正式渲染前，每拍渲一帧静帧检查：是否在网格上、是否拥挤、是否易读。
</build>

<gotchas>
被镜头缩放的元素、带文字的元素不要加 will-change，否则文字会糊。
在变形容器里切换的文字要有自己的进场和出场时间，否则新旧文字会叠在一起。
最后一帧必须与第一帧一致：所有弹簧的最后一次目标改变不晚于 13.0s，到 14.0s 已静止。
字体加载完（document.fonts.ready）再置 window.ready = true。
</gotchas>

<start>
按小节顺序制作，每个小节完成后渲静帧检查；全部完成后渲 960×540 小样核对节奏，再出正式版和抽帧图验收，然后交付。
</start>
```
